# أجازاتي

لوحة عربية للحضور والورديات والإجازات. الواجهة ثابتة (`index.html`, `theme.css`, `firebase-cloud.js`) وتستخدم Firebase Authentication وCloud Firestore. يدعم المظهر النهاري والليلي، والجداول على الشاشات الكبيرة وبطاقات الأيام على الهاتف.

## تشغيل محلي

```sh
python build_public.py
python -m http.server 8080
```

افتح `http://localhost:8080`. يتطلب الدخول مشروع Firebase المعرّف في `FIREBASE_CONFIG` في `index.html` وحسابًا موجودًا. لا تخزّن كلمات المرور في المستودع.

لرؤية الواجهة دون حساب أو بيانات حقيقية، افتح `http://localhost:8080/?preview=1`. المعاينة للقراءة فقط وتستخدم أسماء وسجلات توضيحية محلية.

## نموذج البيانات والصلاحيات

- `employeeAccounts/{uid}`: ربط حساب Authentication بهوية الموظف وفريقه وإدارته؛ المدير فقط ينشئ أو يعدل أو يحذف الملف.
- `staff/{employeeId}`: بيانات الدليل والأرصدة، ولا يقرأ الموظف سوى مجموعة فريقه وإدارته.
- `teamMembership/{employeeId}`: مرجع الصلاحية للفريق والإدارة؛ المدير فقط يغيره.
- `attendance/{date}/records/{employeeId}`: سجل واحد لكل موظف في كل تاريخ؛ تعديل الموظف مقصور على زميل في مجموعته وبقيم محددة.
- `meta/workspace`: إعدادات الوردية؛ التعديل للمدير فقط.
- `shared/workspace`: بيانات قديمة للترحيل، لا يقرأها إلا المدير ولا تقبل كتابة جديدة.

صلاحية المدير تعتمد على Firebase Auth custom claim باسم `admin: true`، ولا تمنحها الواجهة. يجب إعداد أول حساب مدير خارج التطبيق بأداة موثوقة تستخدم Firebase Admin SDK. لا تنشر مفتاح حساب خدمة في المتصفح أو المستودع.

## الترحيل والنشر

1. خذ نسخة احتياطية من Firestore وAuthentication قبل التغيير. راجع بيانات `shared/workspace` والحسابات الموجودة.
2. انشر القواعد والفهرس: `firebase deploy --only firestore`، ثم انشر ملفات `public` على الاستضافة المختارة بعد `python build_public.py`.
3. **ادخل بحساب مدير أولًا.** ينتقل التطبيق تلقائيًا من `shared/workspace` إلى المستندات الجديدة ويضع `legacyMigrated: true` بعد اكتمال الكتابة. العملية قابلة للإعادة إذا انقطعت قبل العلامة.
4. تحقق من عدد الموظفين وسجلات الحضور لكل شهر، ثم جرّب حساب موظف من فريق محدد. لا تحذف المستند القديم قبل المطابقة والنسخ الاحتياطي.

الموظف الذي يدخل قبل اكتمال ترحيل المدير قد لا يرى سجلاته. أسماء المستخدمين القديمة ذات كلمة المرور المشتركة `1234567` تحتاج تدوير كلمات المرور بعد النشر. الحساب المحذوف يفقد الوصول إلى Firestore عند حذف ملفه، لكن هوية Firebase Authentication تبقى؛ على المدير تعطيلها أو حذفها من لوحة Firebase. لا يمكن للمتصفح حذف هوية مستخدم آخر بأمان.

## إدارة الحسابات والنسخ الاحتياطية

المدير ينشئ حساب الموظف بكلمة مرور عشوائية تظهر مرة واحدة؛ يسلّمها للموظف عبر قناة آمنة. لا يوجد تسجيل ذاتي. تعديل بيانات الموظف والأرصدة للمدير، بينما يستطيع الموظف تعديل حضور زملاء فريقه وإدارته فقط. استعادة JSON تستبدل سجلات الحضور وإعدادات الورديات، وتتطلب أن تطابق معرفات الموظفين الموجودين؛ لا تنشئ أو تستعيد حسابات Authentication.

## التحقق

```sh
python build_public.py
node --check firebase-cloud.js
npm ci && npm test
```

يشغّل `npm test` اختبارات الصلاحيات على Firestore Emulator دون بيانات اعتماد حقيقية. اختبر الترحيل والهوية الحقيقية في بيئة تجريبية أيضًا قبل نشر القواعد على بيانات العمل.
