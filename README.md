# تطبيق الحضور والورديات

واجهة عربية لإدارة الموظفين والحضور والإجازات مع حفظ البيانات المشتركة في Cloud Firestore. يفتح التطبيق مباشرة دون شاشة تسجيل دخول، ويستطيع كل من يملك الرابط مشاهدة البيانات وتعديلها. يحتوي على تصدير Excel ونسخ احتياطي JSON.

يمكن تعيين الموظف إلى إحدى أربع فرق: الحمراء والزرقاء والصفراء بنظام المناوبة، أو الفريق الصباحي الذي يعمل وردية صباحية ثابتة طوال الشهر. يعرض الجدول وردية كل موظف على حدة.

**رابط التطبيق المنشور:** https://shifts-attendance-am-2026.web.app

## تشغيل محلي اختياري

```powershell
python server.py
```

افتح `http://localhost:8080`. يمكن فتح `index.html` مباشرة، لكن تشغيله عبر الخادم المحلي أفضل لاستخدام وحدات Firebase.

## Firebase

المشروع السحابي [Shifts Attendance](https://console.firebase.google.com/project/shifts-attendance-am-2026/overview) متصل بالتطبيق، وقواعد `firestore.rules` منشورة. يستخدم التطبيق اتصالاً تلقائياً غير مرئي عبر Firebase Authentication للوصول إلى مساحة بيانات مشتركة `shared/workspace`.

افتح رابط التطبيق؛ ستظهر بيانات الحضور المشتركة تلقائياً بعد اكتمال التحميل. تعديلات خلايا الحضور تُحفظ على مستوى الخلية كي لا يستبدل تعديل شخص تعديل شخص آخر في اليوم نفسه.

البيانات متاحة لكل زائر للرابط، بما فيها إضافة الموظفين وحذفهم وتعديل الحضور؛ احتفظ بنسخة احتياطية دورية من زر قاعدة البيانات.

## ملاحظات التشغيل

- يحتفظ Firestore بنسخة محلية للمزامنة عند انقطاع الاتصال بعد تحميل التطبيق، لكن ملفات الواجهة تأتي من شبكات CDN؛ أول تشغيل يحتاج إنترنت.
- سجل الحضور محفوظ حالياً في مستند Firestore واحد. إذا زاد حجم البيانات كثيراً، ينبغي توزيع السجلات على مستندات منفصلة قبل بلوغ حد المستند.
- التطبيق يستخدم Firebase فقط؛ ملف Supabase القديم غير مستخدم وغير مرفوع إلى المستودع.

## تحديث الموقع المنشور

بعد تعديل `index.html` أو `firebase-cloud.js`، شغّل `python build_public.py` ثم `npx firebase-tools deploy --only hosting`. مجلد `public` يحتوي على ملفات الواجهة المنشورة فقط.
