# تطبيق الحضور والورديات

واجهة عربية لإدارة الموظفين والحضور والإجازات مع حفظ البيانات في Cloud Firestore. يسجل الموظف الدخول بكوده وكلمة المرور، أو ينشئ حساباً جديداً من شاشة الدخول باسمه وإدارته وكوده وورديته. يرى الموظف زملاءه في نفس الوردية والإدارة، ويمكنه تعديل حضورهم وأسمائهم وأرصدة الإجازة الاعتيادية والعارضة وساعات الأذونات. يمكنه مسح حالة يوم وإعادتها فارغة. تعرض الواجهة كل أيام الشهر، ويوم الجمعة راحة ثابتة للوردية الصباحية.

يمكن تعيين الموظف إلى إحدى أربع ورديات: الحمراء والزرقاء والصفراء بنظام المناوبة، أو الوردية الصباحية الثابتة طوال الشهر. يعرض الجدول وردية كل موظف على حدة.

الموظفون الحاليون: أحمد نادر (5686) ومحمد سالم (5979) في الوردية الحمراء بإدارة دعم المستخدمين، ومحمد علاء خليل (7091) في الوردية الصباحية بإدارة البنية التحتية. يمكن تسجيل موظفين جدد من شاشة الدخول.

## تشغيل محلي اختياري

```powershell
python server.py
```

افتح `http://localhost:8080`. يمكن فتح `index.html` مباشرة، لكن تشغيله عبر الخادم المحلي أفضل لاستخدام وحدات Firebase.

## Firebase

المشروع السحابي [Shifts Attendance](https://console.firebase.google.com/project/shifts-attendance-am-2026/overview) متصل بالتطبيق. يستخدم Firebase Authentication حساباً لكل موظف، مع كلمة مرور أولية `1234567` يمكن تغييرها من «حسابي». الإدارتان المتاحتان هما «دعم المستخدمين» و«البنية التحتية».

حساب أحمد نادر (5686) هو حساب الإدارة الكامل، ويبدأ بلا وردية محددة حتى يختارها. يمكنه اختيار أي وردية وتسجيل موظفين وتعديل بياناتهم. يمكن للموظف أيضاً تسجيل نفسه من شاشة الدخول. يستطيع كل موظف تعديل بياناته وأرصدة زملائه في نفس الوردية والإدارة؛ تغيير الوردية والإدارة وإضافة الموظفين وحذفهم للإدارة فقط. يمكن لكل موظف تغيير كلمة مروره من «حسابي» بإدخال الكلمة الحالية والجديدة وتأكيدها. كلمة مرور حساب الإدارة خاصة به وغير محفوظة في المستودع.

تعديلات خلايا الحضور تُحفظ على مستوى الخلية. بيانات الموظفين والحضور محفوظة حالياً في مستند مشترك؛ تسمح قواعد Firestore لحسابات الموظفين بقراءة المستند كله، بينما تقصر الواجهة العرض على الوردية المختارة وتمنع تعديل وردية أخرى. يمكن للإدارة إنشاء نسخة احتياطية JSON من زر قاعدة البيانات.

## ملاحظات التشغيل

- يحتفظ Firestore بنسخة محلية للمزامنة عند انقطاع الاتصال بعد تحميل التطبيق، لكن ملفات الواجهة تأتي من شبكات CDN؛ أول تشغيل يحتاج إنترنت.
- سجل الحضور محفوظ حالياً في مستند Firestore واحد. إذا زاد حجم البيانات كثيراً، ينبغي توزيع السجلات على مستندات منفصلة قبل بلوغ حد المستند.
- التطبيق يستخدم Firebase فقط؛ ملف Supabase القديم غير مستخدم وغير مرفوع إلى المستودع.

## تحديث الموقع المنشور

بعد تعديل `index.html` أو `firebase-cloud.js`، شغّل `python build_public.py`، ثم ارفع التغييرات إلى الفرع `main` على GitHub لينشرها Vercel تلقائياً. مجلد `public` يحتوي على ملفات الواجهة المنشورة فقط. لتحديث نسخة Firebase Hosting وقواعد الصلاحيات أيضاً، شغّل `npx firebase-tools deploy --only firestore:rules,hosting`.
