# أجازاتي

لوحة عربية للحضور والورديات والإجازات. الواجهة ثابتة (`index.html`, `theme.css`, `firebase-cloud.js`) وتستخدم Firebase Authentication وCloud Firestore. يدعم المظهر النهاري والليلي، والجداول على الشاشات الكبيرة وبطاقات الأيام على الهاتف.

## تشغيل محلي

```sh
python build_public.py
python -m http.server 8080
```

افتح `http://localhost:8080`. يتطلب الدخول مشروع Firebase `agazaty` وحسابًا موجودًا. لا تخزّن كلمات المرور أو حساب الخدمة في المستودع.

لرؤية الواجهة دون حساب أو بيانات حقيقية، افتح `http://localhost:8080/?preview=1`. المعاينة للقراءة فقط وتستخدم أسماء وسجلات توضيحية محلية.

## نموذج البيانات والصلاحيات

- `employeeAccounts/{uid}`: ربط حساب Authentication بهوية الموظف وفريقه وإدارته؛ المدير فقط ينشئ أو يعدل أو يحذف الملف.
- `staff/{employeeId}`: بيانات الدليل والأرصدة، ولا يقرأ الموظف سوى مجموعة فريقه وإدارته.
- `teamMembership/{employeeId}`: مرجع الصلاحية للفريق والإدارة؛ المدير فقط يغيره.
- `attendance/{date}/records/{employeeId}`: سجل واحد لكل موظف في كل تاريخ؛ تعديل الموظف مقصور على زميل في مجموعته وبقيم محددة.
- `meta/workspace`: إعدادات الوردية؛ التعديل للمدير فقط.
- `shared/workspace`: بيانات قديمة للترحيل، لا يقرأها إلا المدير ولا تقبل كتابة جديدة.

صلاحية المدير تعتمد على Firebase Auth custom claim باسم `admin: true`، ولا تمنحها الواجهة. يجب إعداد أول حساب مدير خارج التطبيق بأداة موثوقة تستخدم Firebase Admin SDK. لا تنشر مفتاح حساب خدمة في المتصفح أو المستودع.

## المشروع الجديد `agazaty`

أُنشئ مشروع Firebase وتطبيق ويب جديدان في حساب المالك، وتم تفعيل Email/Password Authentication. أُنشئت قاعدة Firestore Standard الافتراضية في `me-central1` (الدوحة)، ونُشرت القواعد وفهرس `records.groupKey` لاستعلامات collection group. لم تنتقل بيانات أو هويات المشروع القديم `shifts-attendance-am-2026` إلى هذا المشروع تلقائيًا، ولم يُنشأ أول حساب مدير بعد.

بعد التحقق من Firestore والقواعد والفهرس، أنشئ أول مدير من بيئة موثوقة تحتوي على اعتماد مشروع **`agazaty`** فقط. حمّل حساب خدمة من إعدادات المشروع واحتفظ به خارج المستودع، ثم شغّل في طرفية خاصة:

```sh
GOOGLE_APPLICATION_CREDENTIALS=/private/path/service-account.json npm run bootstrap:admin -- admin@example.com
```

يُنشئ الأمر مستخدمًا جديدًا بكلمة مرور عشوائية، ويمنحه `admin: true`، ويعرض كلمة المرور مرة واحدة. إذا كان البريد موجودًا، يتوقف دون منحه صلاحية. لا تشغّل الأمر في سجلات CI، وغيّر كلمة المرور بعد الدخول. يتطلب هذا الإجراء الوصول الإداري إلى المشروع؛ لا تستطيع واجهة المتصفح منح claim المدير.

## الترحيل والنشر

1. خذ نسخة احتياطية من Firestore وAuthentication في **المشروع القديم** قبل التغيير. راجع بيانات `shared/workspace` والحسابات الموجودة.
2. قاعدة Firestore وقواعدها وفهرسها منشورة في مشروع `agazaty`. عند تعديلها لاحقًا، انشرها من المستودع: `firebase deploy --only firestore --project agazaty`، وبعدها انشر ملفات `public` على الاستضافة المختارة بعد `python build_public.py`.
3. لن يجد المشروع الجديد `shared/workspace` القديم. إذا حصلت على تصدير موثوق للمستند القديم، استورده إلى `shared/workspace` في المشروع الجديد من بيئة إدارية آمنة قبل دخول المدير أول مرة. **ادخل بحساب المدير أولًا**؛ ينقل التطبيق المستند القديم الموجود في *نفس المشروع* إلى المستندات الجديدة ويضع `legacyMigrated: true` بعد اكتمال الكتابة.
4. هويات Firebase Authentication لا تنتقل بهذا الترحيل. أنشئ الحسابات المقابلة للموظفين في المشروع الجديد، ثم تحقق من عدد الموظفين وسجلات الحضور لكل شهر ومن حساب موظف في فريق محدد. لا تحذف المصدر قبل المطابقة والنسخ الاحتياطي.

الموظف الذي يدخل قبل اكتمال ترحيل المدير قد لا يرى سجلاته. كلمات المرور القديمة المشتركة لا تُنقل إلى المشروع الجديد؛ أنشئ كلمات مرور فردية. الحساب المحذوف يفقد الوصول إلى Firestore عند حذف ملفه، لكن هوية Firebase Authentication تبقى؛ على المدير تعطيلها أو حذفها من لوحة Firebase. لا يمكن للمتصفح حذف هوية مستخدم آخر بأمان.

## إدارة الحسابات والنسخ الاحتياطية

المدير ينشئ حساب الموظف بكلمة مرور عشوائية تظهر مرة واحدة؛ يسلّمها للموظف عبر قناة آمنة. لا يوجد تسجيل ذاتي. تعديل بيانات الموظف والأرصدة للمدير، بينما يستطيع الموظف تعديل حضور زملاء فريقه وإدارته فقط. استعادة JSON تستبدل سجلات الحضور وإعدادات الورديات، وتتطلب أن تطابق معرفات الموظفين الموجودين؛ لا تنشئ أو تستعيد حسابات Authentication.

## التحقق

```sh
python build_public.py
node --check firebase-cloud.js
npm ci && npm test
```

يشغّل `npm test` اختبارات الصلاحيات على Firestore Emulator دون بيانات اعتماد حقيقية. اختبر الترحيل والهوية الحقيقية في بيئة تجريبية أيضًا قبل نشر القواعد على بيانات العمل.
